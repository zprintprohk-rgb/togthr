## 8. Memory note (cross-project)

Saved to agent memory (per `MEMORY.md` index) — this is the **third time** in this project the OpenNext + CF Workers per-page `handler.mjs` bundle dispatch bug has manifested:

- 2026-07-21 03:00 → bug first suspected (7/21 page 404 despite build success)
- 2026-07-21 09:48 → bug confirmed via 5-step deep investigation
- 2026-07-21 18:00 → bug still present 8h later, 5 GH Actions success deploys failed to clear it

**Permanent lesson (cross-project, for any OpenNext + Cloudflare project)**:
- `npm run build` + `wrangler deploy` **success** does NOT guarantee live page render.
- Always do a **post-deploy live curl** on each new dynamic route, not just trust the deploy step.
- For per-page routes added **after** the initial OpenNext build, the wrangler bundle's URL→M dispatch table can silently omit the new route even when the build manifest, prerender manifest, and routes manifest all include it. The result is HTTP 404 with full Next.js headers (not 502/500) and a different ETag per request (no edge cache).
- **Recovery**: hard revert all 7/21-related commits and re-push as a single fresh commit. Or, if the wrangler version has a known fix, upgrade wrangler + @opennextjs/cloudflare together.
